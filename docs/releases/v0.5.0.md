# InterLude 0.5.0

Sonos speakers, speakers that appear and disappear as they join and leave the network, one interface on every device, browsing without stopping what's playing, a new BBC station, and a server whose page and station list can change while it runs. Nothing about how bulletins are found has changed.

## What's new

- **Sonos speakers.** InterLude plays on Sonos rooms and groups as well as Chromecasts, from the Mac app, the phone remote and the server. Groups appear as the Sonos app names them ("Kitchen + 2") and follow regrouping there.
  - Sonos can't play HLS, so InterLude gives it one continuous AAC stream made from the same playlist, with the same delay and the same news muted or skipped. It plays as an internet radio station.
  - The speaker's own controls work alongside InterLude: its volume moves InterLude's slider, Pause or Stop there stops InterLude, and Play there starts it again.
  - If the speaker can't open the stream, InterLude says so and points at a firewall, rather than waiting in silence.
- **Speakers as they come and go.** Speakers you add or remove appear in and leave the speaker list as it happens. The server now listens to multicast DNS all the time instead of looking every two minutes: a speaker shows up when it announces itself, goes when it says goodbye, and drops out about a minute after it stops answering if it was simply unplugged.
- **One interface everywhere.** The Mac's menu bar panel is now the same "On air" app as the phone remote and the server's web page, so all three look and work alike.
  - The panel and its Settings are the web app in a window of their own, served by InterLude itself. Sound still plays through the Mac or your speakers, so closing the panel doesn't stop it.
  - One Settings sheet everywhere, now with the longest mute and bulletin minutes on the server too. The Mac's own options (start at login, keep awake, port, phone remote, diagnostics, quit) appear only in the Mac's panel.
  - Phones and the server gain what the Mac panel had: a Mute news switch, the list of recent mutes with **Wasn't news**, favourite stations, and **Try again** or **Play on this Mac** after an error.
  - On a wide window or desktop browser, the player stays on the left and Earlier, the news and Settings open beside it.
- **Browse while you listen.** Live and Earlier are now views rather than switches. Looking through Earlier, stepping through the days, or opening another station's programmes leaves what's playing alone, on the Mac and in the web app.
  - Back in Live with an earlier programme or another station still playing, **Play … live instead** switches to the station live.
  - On the Mac, the programme list stays open under an earlier programme as it plays, with a speaker beside the one playing.
  - The player's artwork and station name follow what's playing, not the station being browsed.
- **6 Music Indie Forever** joins the station list. Saved station lists on the server now pick up new stations, as the Mac app's already did.
- **Station list changes take effect at once.** Edit `stations.json`, for example to fix a pool ID after the BBC changes one, and InterLude reads it again within a few seconds. Playback carries on, restarting only if the playing station's stream address changed.
- **Server: change the page and stations without a rebuild.** A `config` folder beside `compose.yaml` can hold a `stations.json` and a `web` folder with the web app's files, each used in place of the image's own. `scripts/push-config.sh` copies them from a checkout. Open pages reload themselves when the web app changes.
- **Server: `:edge` images.** Each change to the server on `main` publishes `ghcr.io/mstrtheplague/interlude-server:edge`. Set `INTERLUDE_TAG=edge` in the environment to follow it.

## Changes for people who build or run it

- The SwiftUI panel and Settings window are gone; the Mac shows `Web/` in a web view. `--demo=` and `--snapshot=` still make screenshots, and `--port` runs a build beside an installed copy.
- The web app is now three plain files in `Web/` (`index.html`, `app.css`, `app.js`) instead of a string in `Remote.swift`. The Mac app bundles them; a `web` folder in Application Support replaces them for trying changes.
- `scripts/push-web.sh` is gone, replaced by `push-config.sh`. A page it left in the server's data volume is ignored, and the server's log says so.
- The server takes `--sonos-host` (or `INTERLUDE_SONOS_HOSTS`, listed in `compose.yaml`) for a Sonos speaker whose multicast DNS doesn't reach it, such as one on another VLAN. One speaker is enough: it describes the whole household. On the Mac, the `sonosHosts` default does the same.
- `serve` also answers `/test/live.aac`, the stream as a Sonos speaker plays it. `INTERLUDE_LIVE_SONOS=<speaker address> INTERLUDE_LIVE_SONOS_URL=<stream URL>` runs a live test on a real Sonos speaker, and `INTERLUDE_LIVE_CAST=1` now also runs the continuous discovery.

## Before you install

- The Mac app needs macOS 26 or later on an Apple silicon Mac.
- Sonos speakers fetch the stream from the Mac or the server on the same port as Chromecasts (TCP 8642 by default), and the server controls them on their TCP port 1400. The Mac app finds Sonos speakers under the same Local Network permission as Chromecasts.
- Not notarised: the first time, allow it under System Settings › Privacy & Security › Open Anyway (steps in the README). Or build it from source.
- The server image is `ghcr.io/mstrtheplague/interlude-server:0.5.0`. Before updating, run `mkdir -p config` beside `compose.yaml` and fetch the new `compose.yaml`, which mounts it. Then `docker compose pull && docker compose up -d`.
- Unofficial and not affiliated with the BBC. It relies on stream addresses the BBC doesn't document, which can change; the station list is editable if they do.
